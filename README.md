# Cogncur → Google Fonts

*English below the line; [Nederlands](#nederlands) further down.*

---

## About this project (English)

This project prepares the connected handwriting font [Cogncur](https://github.com/syboor/cogncur),
designed by Liesbeth Flobbe, for submission to Google Fonts. Cogncur is a school cursive used to
teach handwriting; a Google Fonts version makes it available in Google Docs, Slides and on the web
without installing anything.

**What it contains**

- A reproducible build with libre tools: the designer's FontForge source (`upstream/`, never
  modified) is exported to UFO and built with `gftools builder`. The manual steps from the
  original `howto.txt` are automated in `scripts/`.
- A test bank (`tests/`) that compares every build with the original font: shaping of every
  letter pair and triple in every feature configuration, broken joins, glyph outlines and the
  GSUB tables. Every intended difference is listed with its reason in `tests/thresholds.yaml`.
- New glyphs needed for the GF Latin Core glyph set, documented in `docs/new-glyphs.md`.
- A website (`web/`) where teachers and the designer can compare the original and the new version,
  watch letters being written, and report problems.

**Why the issues are in Dutch**

The font is mainly used in Dutch-speaking schools. Design questions are discussed with
the designer and with teachers in Dutch, in GitHub issues labelled `beslissing` (decision): each
option is a comment and people vote with 👍. Feedback from the website arrives as issues through
the forms in `.github/ISSUE_TEMPLATE/`. Code, commit messages and developer documentation
(`CLAUDE.md`) are in English. Questions and pull requests in English are welcome.

**Build**

Requires Python 3.13, FontForge (with Python) and HarfBuzz (`hb-shape`, `hb-view`).

```sh
make venv        # Python environment with the font tools
make upstream    # fetch the original source at the commit pinned in upstream.lock
make all         # export sources → build → test → fontbakery / diffenator2
```

Reports are written to `tests/report/`.

**Authors and use of AI tools**

The type design is by Liesbeth Flobbe: every letter, join and variant in this font comes from her
original source. Simon Vanherweghe maintains this project.

The conversion was built with the help of an AI coding assistant (Anthropic's Claude, via
Claude Code), under the maintainer's direction and review. The AI tools were used for:

- the build and test scripts, the test bank and the website;
- positioning the designer's existing accents on letters she had not accented yet
  (`scripts/composites.py`). Positions that had to be guessed are listed for review and can be
  overridden in `sources/anchors.yaml`;
- first drafts of a small number of new glyphs (see `docs/new-glyphs.md`). These are built from
  the designer's own strokes and the same pen settings. They are put to the designer for approval
  in the `ontwerper` issues before they are final.

No glyph shapes were generated by an image or font-generating AI model.

reflected in the license is still being settled.

## Nederlands

Dit project zet het verbonden schrijfletterfont [Cogncur](https://github.com/syboor/cogncur) van Liesbeth Flobbe om naar een versie die bij Google Fonts ingediend kan worden. Zo kan het ook gebruikt worden in Google Docs, Google Slides en op websites, zonder installatie.

**Over de naam.** De licentie van het origineel (SIL Open Font License, zie `LICENSE.txt`) reserveert de naam "Cogncur".

## Wat zit erin

- **Een automatische build**: van het originele FontForge-bestand naar een UFO-bron en een TTF via `gftools builder`. De handmatige stappen uit het origineel (`howto.txt`) zitten nu in scripts.
- **Een testbank**: vergelijkt de nieuwe build met het originele lettertype. Ze controleert vooral de verbindingen tussen de letters en checkt dat elke nieuwe letter zich gedraagt als de letter waarop hij gebaseerd is.
- **Nieuwe tekens** voor de tekenset die Google Fonts vraagt. `docs/new-glyphs.md` beschrijft per teken waar het van afgeleid is. Een deel ervan zijn nog schetsen die op een beslissing wachten.
- **Een vergelijkingstool**: het origineel en de nieuwe versie over elkaar of onder elkaar, met tekst die je zelf intypt.

## Gebruik

Vereist: Python 3.13, FontForge (met Python) en HarfBuzz (`hb-shape`, `hb-view`). Voor de website: Node 24 met npm.

```sh
make venv        # Python-omgeving met de font-tools
make upstream    # haalt het origineel op (vastgezette versie in upstream.lock)
make all         # bron maken → bouwen → testen → Google Fonts-controles
make web-data    # lettertype en gegevens voor de website naar web/public/ (daarna committen)
make serve       # de website lokaal op http://localhost:4321/cogncur-tex/
make designer    # bestanden voor de ontwerper opnieuw maken (zie hieronder)
```

Rapporten komen in `tests/report/`. Meer uitleg voor ontwikkelaars staat in `CLAUDE.md`.

## Na een wijziging aan een teken

De issues voor de ontwerper (label `ontwerper`) linken naar bewerkbare SVG- en EPS-bestanden in
`docs/ontwerper/`. Die worden niet vanzelf bijgewerkt. Na elke wijziging aan een teken:

1. `make designer`: bouwt het lettertype opnieuw en maakt de bestanden opnieuw.
2. Commit en push `docs/ontwerper/` naar `main`. De links in de issues wijzen altijd naar `main`,
   dus de ontwerper ziet dan meteen de nieuwe versie. Je hoeft in de issues niets aan te passen.

Komt er een nieuw issue voor de ontwerper bij? Zet de tekens in `"bestanden"` in
`scripts/issues.py`, doe stap 1 en 2, en daarna `.venv/bin/python scripts/issues.py --files`
(dat plaatst de reactie met de links, maar nooit twee keer).

## Een nieuwe versie uitbrengen

De website toont standaard de nieuwste versie. Wat er nog in ontwikkeling is, staat ernaast en
oudere versies blijven bekijkbaar (pagina **Versies**).

1. Maak een mijlpaal: `.venv/bin/python scripts/release.py milestone 1.001`. Zet op GitHub de
   issues die in die versie komen in de mijlpaal "Versie 1.001", en sluit ze als ze klaar zijn.
2. `make release V=1.001`: verhoogt het versienummer, bouwt en test het lettertype, bewaart een
   kopie voor de website, schrijft de lijst met afgesloten issues en de veranderde tekens, en
   maakt een commit en een tag. Dit blijft op je eigen computer.
3. `make publish V=1.001`: zet alles op GitHub, maakt de release met het lettertype en sluit de
   mijlpaal. De website wordt daarna vanzelf bijgewerkt.
